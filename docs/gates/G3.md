### Key Test Case Verifications
1. **Ownership Isolation (`ownership-isolation.spec.ts`):**
   - Alice creates config `cfg_...` with `owner_id = 'tenant-alice'`.
   - Bob attempts `getConfiguration(cfg_id, 'tenant-bob')` -> Throws `NotFoundError` (status 404, code `NOT_FOUND`).
   - The error message and response are identical to a non-existent ID; no leakage of existence or owner metadata.
2. **Revision Conflict & CAS (`revision-conflict.spec.ts`):**
   - Config created at `current_revision = 1`.
   - CAS update with `expectedRevision = 1` increments `current_revision` to `2` and inserts `industrial_configuration_revision` rev 2.
   - Subsequent CAS update with stale `expectedRevision = 1` throws `RevisionConflictError` (HTTP 412, code `REVISION_CONFLICT`).
   - Append-only revision history preserves both revisions.
3. **Idempotency (`idempotency.spec.ts`):**
   - Request 1 with key `k1` and body `{ ... }` executes work and records `state = 'completed'`.
   - Request 2 with same key `k1` and identical body returns cached result (`cached: true`), skipping handler.
   - Request 3 with same key `k1` and modified body throws `IdempotencyConflictError` (HTTP 409, code `IDEMPOTENCY_CONFLICT`).
4. **Database UNIQUE Constraints (`unique-constraints.spec.ts`):**
   - Duplicate `(configuration_id, revision)` in `industrial_configuration_revision` throws PostgreSQL error `23505`.
   - Duplicate `(variant_id, revision)` in `industrial_technical_snapshot` throws PostgreSQL error `23505`.
   - Duplicate `(owner_id, operation, key_hash)` in `industrial_idempotency` throws PostgreSQL error `23505`.
5. **Canonical Hash Stability (`hash-stability.spec.ts`):**
   - Object key permutations at arbitrary depths produce identical SHA-256.
   - Volatile signed download URLs (differing in `token`, `expires`, `request_id`) normalize to identical content SHA-256.
